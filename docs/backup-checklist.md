# 原始分区备份验收标准

**当前没有完成原始分区备份。** 本页是取得足够临时权限后的执行与验收要求，不是声称现在已可备份的脚本。

1. 重新记录构建指纹、启动槽位、Verified Boot 状态和完整分区符号链接映射。不得把旧记录中的 `mmcblk0p25` 当作其他固件的固定编号。
2. 获取每个实际存在分区的真实块设备路径和精确字节长度。区分 A/B 槽、逻辑分区与容纳逻辑分区的 super；不要根据别的设备猜分区列表。
3. 对恢复启动链所需的原始分区先做只读导出。包括 boot、dtbo、vbmeta 等实际存在的分区及相应槽位；init_boot/vendor_boot/recovery 仅在本机确实存在时处理。
4. 保存到电脑私有目录，输出先使用 `.partial`。分区读取进程、传输和本地写入都必须成功；不能因管道最后一条命令返回 0 就认为源端读取成功。
5. 比较镜像字节数与块设备长度，计算本地 SHA-256。能够在设备上计算原始分区哈希时，应与本地核对；否则独立再读一份，在设备静止、分区不被改写的前提下比较完整摘要。来源或一致性无法确认时明确标为未验证。
6. 成功后才重命名为最终镜像，并记录时间、固件、槽位、分区名、源设备、长度、摘要和命令返回值。再保存一份离线副本。
7. 诊断 ELF、CIL、已安装 APK、设置导出、截图及空文件不计入原始分区备份。普通运行状态下复制可变 userdata 也不能称作一致的整机备份。

固件镜像和校准分区可能包含设备专有信息，不上传本公开仓库。这里没有分区写入、切槽、刷机或清数据步骤。
